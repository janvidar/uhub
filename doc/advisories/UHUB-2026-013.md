# UHUB-2026-013 — `!kick`, `!redirect` and `!ban` ignore rank (issue #134)

- **Severity:** Low
- **Attack vector:** Network, by an operator
- **Impact:** An operator can kick, redirect or ban users ranked at or above
  them -- other operators, super users and admins. `!ban` is cluster-wide and
  persistent, so an operator can lock an admin out of every node of a linked
  hub
- **CVSS 3.1 (suggested):** 3.8 — `AV:N/AC:L/PR:H/UI:N/S:U/C:N/I:L/A:L`
- **Affected:** `!kick` in every release from 0.3.0 to 0.8.2 (0.2.x did not
  implement it); `!ban` from 0.7.0; `!redirect` from 0.7.1
- **Fixed in:** 0.8.3 (commit `a8ce0f1` on 0.8.x-stable; `b6be8ca` on master)
- **Reported by:** Kcchouette

## Description

The three commands are available to operators and up. Their only check on the
target was that it is not the caller:

```c
if (target == user)
	cbuf_append(buf, "Cannot kick yourself.");
else
	/* kick */
```

Nothing compared the two users' ranks, so an operator could act on an admin as
easily as on a guest. With `!ban` that means the admin is disconnected, their
CID and nick are banned, the ban is stored by a storage plugin that keeps bans,
and on a linked hub it is propagated to every node.

## Remediation

Upgrade to **uhub 0.8.3** or later. The three commands now act only on users of
a lower rank than the caller, which is the rule the account commands already
followed. A user on a linked hub is ranked by the client type (`CT`) their own
hub gave them, so a local operator cannot ban a remote admin either.

No configuration or protocol change.

## Workarounds

Grant operator status only to users trusted with every account below admin.
