# UHUB-2026-006 — Link command injection through a nick on an `auth_proxy` slave

- **Severity:** Critical
- **Attack vector:** Network, unauthenticated, no user interaction. Only hubs
  with `auth_proxy = 1` and an established link to their auth master
- **Impact:** An unauthenticated client makes the slave send arbitrary link
  commands to the master, which runs them as coming from a trusted hub
  (e.g. adding or lifting cluster-wide bans)
- **CVSS 3.1 (suggested):** 9.1 — `AV:N/AC:L/PR:N/UI:N/S:U/C:N/I:H/A:H`
- **Affected:** uhub 0.7.0 – 0.8.0, when `auth_proxy` is enabled
- **Fixed in:** 0.8.1 (commit `75f0aaa`)
- **Reported by:** Kcchouette (GitHub issue #128)

## Description

A hub with `auth_proxy = 1` keeps no accounts of its own. On a client's first
`BINF` it asks its master whether the nick is registered, sending
`LACQ <sid> <nick>` over the link. The link protocol is line-based and has no
escaping.

The slave took the nick from the `BINF`, decoded its ADC escapes, and sent it
to the master **before** the login checks had validated it:

```c
char* tmp = adc_msg_get_named_argument(cmd, ADC_INF_FLAG_NICK);
char* nick = tmp ? adc_msg_unescape(tmp) : NULL;   /* "\n" is a real newline now */
int sent = nick ? link_auth_query(hub, user, nick) : 0;
```

ADC escapes a newline as `\n`. A nick such as `x\nLBAN 0 <CID> victim reason`
therefore arrives at the master as two lines:

```
LACQ AAAB x
LBAN 0 <CID> victim reason
```

The master answers the `LACQ` and then runs the injected command as if it came
from the slave. The slave rejects the nick afterwards, but by then the master
has already acted. Any link command can be injected this way, for example
`LBAN` to ban and disconnect users across the cluster, or `LUBN` to lift a ban.

No account is needed, and the link secret is not involved: the injected line
travels over the slave's own authenticated link.

## Remediation

Upgrade to **uhub 0.8.1** or later. The slave now validates the nick with the
normal login checks before querying the master, and sends the validated nick.
Independently, every line written to a link now goes through one check that
refuses any line with an embedded CR or LF, so a field that slips past
validation elsewhere is dropped rather than injected.

The `LACQ` wire format is unchanged. (0.8.1 still has to be deployed across
the whole cluster because of UHUB-2026-005.)

## Workarounds

- Set `auth_proxy = 0` on reachable slaves (they then log users in locally,
  without the master's accounts).
- Otherwise, restrict who can reach the slave's client port.
