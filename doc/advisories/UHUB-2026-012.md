# UHUB-2026-012 — Any client can send messages as the hub itself (issue #131)

- **Severity:** Medium
- **Attack vector:** Network, by any user who can log in, no user interaction.
  On a hub that admits guests (the default) that is anyone
- **Impact:** Messages that clients show as coming from the hub: forged hub
  announcements in the main chat, and private messages "from the hub" asking
  users for their password or sending them elsewhere
- **CVSS 3.1 (suggested):** 5.3 — `AV:N/AC:L/PR:N/UI:N/S:U/C:N/I:L/A:N`
  (`PR:L`, 4.3, with `registered_users_only = yes`)
- **Affected:** all uhub releases up to 0.8.2. The check has had this shape
  since the first commit in the repository (2009); verified exploitable on
  0.8.2
- **Fixed in:** 0.8.3 (commit `7e2ba38` on 0.8.x-stable; `700c4e9` on master)
- **Reported by:** Kcchouette

## Description

Every B (broadcast), D (direct), E (echo) and F (feature) message names its
sender by SID, and `adc_msg_parse_verify()` (`src/adc/message.c`) refuses one
whose SID is not the sender's own:

```c
if (command->source && (!u || (command->source != u->id.sid && ...)))
	/* refuse */
```

The test is on the parsed SID's *value*. `string_to_sid("AAAA")` is 0, and
`AAAA` is the SID the hub reserves for itself, so a message claiming to come
from the hub skips the check and is relayed as it is. A logged-in client
sending

    BMSG AAAA Please\slog\sin\sagain\sat\s...

has every other user see a main-chat message from the hub, and `DMSG AAAA
<their SID> ...` does the same in private. Clients give the hub's messages more
trust than a user's, which is what makes this useful for phishing.

Only `AAAA` gets through: the parser checks that each SID character is base32
before converting it, so a malformed SID is still refused.

## Remediation

Upgrade to **uhub 0.8.3** or later. The check now decides by the message
context whether there is a source to verify, and refuses SID 0 for every
sender, unrestricted bots (`ubot`, `opubot`) included.

No configuration or protocol change.

## Workarounds

None that close it. `registered_users_only = yes` limits it to registered
users.
